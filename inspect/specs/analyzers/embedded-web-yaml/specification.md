# Embedded Web and YAML Adapter Specification

## Identity, license, and authority

This specification covers embedded Web/YAML behavior within `org.sonarsource.javascript:sonar-javascript-plugin:13.4.0.43982:multi`, bundled by Community Build `26.8.0.126808`. Source authority is SonarSource/SonarJS tag `13.4.0.43982`, commit `d02b514f8007f18a798876fc9361b9c233ab2f02`. Analyzer-owned source uses Sonar Source-Available License v1.0 (`LicenseRef-SSAL-1.0`); parser dependencies retain separate notices. [I1][I2]

## Purpose, scope, dependencies, and strict non-ownership

Adapter selects eligible HTML and AWS SAM/CloudFormation YAML hosts, extracts inline JavaScript, analyzes fragments as main JavaScript without TypeScript program, projects issues, suppressions, parser locations, and quick-fix edits into host coordinates, and analyzes CSS-family style blocks in configured HTML/Vue hosts. It owns no rule repository and no rule semantics. Inherited JavaScript keys remain `javascript:S…` and inherited CSS keys remain `css:S…`; catalogs are owned by `../javascript/specification.md` and `../css/specification.md`. Shared bridge/runtime is owned once by JavaScript specification. [E1][B2]

Adapter does not own or write host NCLOC, comment lines, complexity, cognitive complexity, functions, statements, classes, executable lines, highlighting, symbols, CPD, or coverage. For `web` hosts, HTML analyzer owns host measures/highlighting/CPD. For `yaml`, Infrastructure-as-Code analyzer owns host measures/highlighting where applicable. For `.vue`, JavaScript analyzer owns full host metrics/highlighting/symbols/CPD; embedded CSS contributes issues only. This ownership rule applies even though fragment analyzer computes temporary snippet NCLOC internally. [B2][E1][C3]

## Host recognition and configuration

`sonar.javascript.html.file.suffixes` defaults to `.html,.htm,.xhtml`. Values are trimmed, lower-cased, dot-prefixed, de-duplicated, and replace defaults. Selection is extension-based and includes main and test indexed files, but extracted JavaScript is always linted with main scope. Inline HTML JavaScript extraction accepts `script` without `src` when type is absent or exactly one supported JavaScript MIME/module value: `module`, `text/javascript`, `application/javascript`, `application/ecmascript`, `application/x-ecmascript`, `application/x-javascript`, `text/ecmascript`, `text/javascript1.0` through `text/javascript1.5`, `text/jscript`, `text/livescript`, `text/x-ecmascript`, or `text/x-javascript`. External-script tags and other types produce no fragment. [B2][E1]

`sonar.javascript.yaml.file.suffixes` defaults to `.yml,.yaml`. A candidate must contain `AWS::Serverless-2016-10-31` and a line-level `Runtime:` value beginning with `nodejs`. Screening is line-based: a line containing `{{` is rejected only when no comment, single-quoted text, double-quoted text, or Codefresh-style variable occurrence matches anywhere on that line. One allowed occurrence therefore permits the whole line even when another raw `{{` also appears. Read failure fails selection. [B2][E1]

Eligible YAML extraction recognizes only `AWS::Lambda::Function` with Node runtime and `Properties.Code.ZipFile`, and `AWS::Serverless::Function` with Node runtime and `Properties.InlineCode`. Accepted scalar formats are plain, block-folded, and block-literal; quoted scalar formats are not extracted. Multi-document YAML is supported. First YAML syntax error aborts extraction and becomes host analysis error. [E1]

`sonar.javascript.css.additional.file.suffixes` defaults to `.vue,.html,.htm,.xhtml`. When at least one CSS rule is active, configured extensions receive PostCSS HTML/Vue parsing and CSS/SCSS/Sass/Less style-block rule execution. Pure CSS metrics/highlighting are deliberately disabled for these hosts. Test host files receive no embedded CSS issues. [B2][C2][C3]

## Extraction, analysis, and projection stages

1. Scanner selects indexed host by suffix/content predicates and sends host text through shared project analysis.
2. Host parser returns zero or more fragments with original text, absolute offset, line starts, scalar format, and optional AWS resource name.
3. A fragment whose average line length exceeds 200 is skipped. Bundle and maximum-file-size filters are not applied to fragments.
4. Fragment parses as JavaScript with no tsconfig or TypeScript program. AWS resource name creates synthetic analysis filename by inserting resource name before host extension; this affects dependency/path-sensitive rule context but not saved file identity.
5. AST nodes, comments, tokens, parser errors, rule locations, suppressions, and quick-fix edits are translated from fragment coordinates to host coordinates. Plain YAML adjusts same-line column; block scalars adjust lines and preserve fragment column. Rules whose reported location falls outside extracted fragment are dropped.
6. Fragment issues and suppressions aggregate across fragments. First JavaScript parsing error aborts remaining fragment processing. Temporary fragment NCLOC and Sonar resolution comments aggregate, but host result writer persists only issues, supported suppressions, and resolution comments for non-`js`/`ts`/`css` hosts.
7. If host suffix also enables CSS, CSS pass merges CSS issues and resolution comments. CSS parse failure is appended as parser failure; other CSS runtime failure is logged and original JavaScript result survives. [E1][B2][C3]

## Outputs, failures, recovery, and lifecycle

Normal output is host-file issues with owning repository key, host primary/secondary ranges, optional gap, and projected quick fixes; supported suppressed issues can be saved as accepted resolutions when platform issue-resolution feature/API is enabled. `sonar-resolve` directives within fragments are projected and processed on host. No fragments is successful no-op. [B2][E1]

HTML host parser is tolerant; malformed inline JavaScript causes JavaScript parser failure. YAML host parser reports first YAML error. Any fragment parse error suppresses all ordinary fragment results for host because project result carries parsing error list. Unknown host result path is skipped. Invalid projected range warns and falls back where possible; per-issue save failure does not stop other issues. Cancellation and shared bridge failures follow JavaScript runtime contract. [B1][B2][E1]

Host markup/YAML, AWS resource names, scalar contents, custom suffixes, and quick-fix edits are untrusted. Implementation must parse without evaluating scripts/templates, apply the specified line-level Helm screening exactly, keep synthetic names from changing saved host identity, range-check every projected edit, and never claim or overwrite outputs owned by HTML, IaC, or JavaScript host analyzers. [E1][B2]

Compatibility depends on htmlparser2 12.0.0, yaml 2.9.0, ESLint/Babel stack from JavaScript specification, and PostCSS/Stylelint stack from CSS specification. Adapter provides no external-report importer and no coverage mapping for fragments. [I1]

## Acceptance scenarios

1. HTML inline script without `src` and with absent/valid type is analyzed; external script and non-JavaScript type are ignored.
2. Two valid HTML fragments produce aggregated owning-JavaScript issues at host ranges; report outside either fragment is discarded.
3. First invalid JavaScript fragment produces projected parser error and prevents ordinary results from later fragments.
4. AWS SAM YAML lacking either transform marker or Node runtime is not selected. A line containing only an unallowed raw Helm token excludes the host, while one allowed occurrence on that line permits it even if another raw token is present.
5. Lambda `ZipFile` and Serverless `InlineCode` in plain/folded/literal forms are extracted; quoted scalar is not.
6. YAML resource name changes only synthetic analysis path; saved issue still belongs to original YAML host.
7. Embedded fragment over 200 average characters per line is skipped without excluding other fragments.
8. Main HTML with CSS block emits CSS issues but adapter writes no CSS or JavaScript host measures; HTML analyzer remains sole host measure owner.
9. Test HTML receives no embedded CSS issues; inline JavaScript still uses adapter's main-scope rule filter as observed.
10. Vue receives JavaScript-owned host artifacts; CSS embedded pass can add issues only and cannot add or replace Vue metrics/highlighting/CPD.
