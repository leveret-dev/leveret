# Java Analyzer Specification

## 1. Identity, release pin, and license

This specification covers the Java analyzer bundled with SonarQube Community Build `26.8.0.126808`: artifact `org.sonarsource.java:sonar-java-plugin:8.37.0.45887`, source repository `https://github.com/SonarSource/sonar-java`, tag `8.37.0.45887`, commit `53f70bdf0f34a64bfe97b71f1bfee07e6d14baa6`. Analyzer-owned source is licensed under `LicenseRef-SSAL-1.0`; this is a full clean-room specification, not a copy marker. [Source: `manifest/component-inventory.md`; `manifest/license-map.md`; `pom.xml`; `sonar-java-plugin/pom.xml`; `LICENSE.txt` at the pinned commit.]

The plugin language key is `java`, language name is `Java`, native rule repository key is `java`, and repository display name is `SonarAnalyzer`. Default recognized suffixes are `.java` and `.jav`. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/Java.java`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaRulesDefinition.java`.]

## 2. Purpose, scope, and exclusions

The analyzer recognizes indexed Java source and test files, constructs syntax and semantic models, resolves project and JDK types from configured bytecode and libraries, executes active native checks, emits issues and source presentation data, computes Java-owned measures, imports JUnit/Surefire-family test execution reports, and imports Checkstyle, PMD, SpotBugs, FindSecBugs, and fb-contrib external issues. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaSensor.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`; `java-surefire/src/main/java/org/sonar/plugins/surefire/SurefireSensor.java`; `external-reports/src/main/java/org/sonar/java/externalreport/`.]

The following contracts are deliberately outside this part:

- Java symbolic execution and its 23 rules are owned by `analyzers/java-symbolic-execution/specification.md`. Those rules extend the same `java` repository but are not part of the 714-rule catalog below. [Source: `manifest/dependency-map.md`; symbolic-execution `JavaSECheckRegistrar.java`.]
- JSP-to-Java transpilation is owned by `analyzers/jsp-java-embedding/specification.md` and is inactive in Community Build. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaPlugin.java`.]
- JaCoCo XML coverage import is owned solely by `integrations/jacoco/`. The Java plugin does not import JaCoCo. It only warns about removed properties `sonar.jacoco.reportPath`, `sonar.jacoco.reportPaths`, `sonar.jacoco.itReportPath`, and `sonar.jacoco.reportMissing.force.zero`. [Source: `manifest/dependency-map.md`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/DroppedPropertiesSensor.java`.]
- Generic project configuration, active-profile precedence, scanner report transport, issue persistence/lifecycle, quality gates, duplication computation, and result presentation remain platform contracts. [Source: `manifest/dependency-map.md`.]
- Commercial repositories such as `javasecurity` and `javabugs` are not bundled Community capabilities and must not be inferred from optional reflective integration points. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/BuiltInJavaQualityProfile.java`; `manifest/component-inventory.md`.]

## 3. Dependencies and owned contracts

The analyzer requires Sonar plugin/scanner services for file indexing, active rules, issue and measure publication, analysis warnings, cache access, and cancellation. Its build targets plugin API `13.8.0.4399` and scanner engine `13.5.0.4089`. [Source: root `pom.xml`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaPlugin.java`.]

The frontend uses Eclipse JDT/ECJ parsing and binding resolution. Project bytecode and dependency archives provide type information; a configured JDK home can replace runtime-JDK class roots. The analyzer owns Java syntax trees, semantic symbols/types, control-flow graphs, class-to-source lookup, native Java issues, Java file measures, highlighting, and symbol references. [Source: `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/classpath/`; `java-frontend/src/main/java/org/sonar/java/DefaultJavaResourceLocator.java`.]

Public extension contracts include `JavaCheck`, `JavaFileScanner`, `IssuableSubscriptionVisitor`, `CheckRegistrar`, `ProfileRegistrar`, `JavaVersionAwareVisitor`, `DependencyVersionAware`, `JavaResourceLocator`, syntax-tree interfaces, semantic symbols/types, control-flow graphs, issue builders, quick fixes, and analyzer cache interfaces. An extension is executed only in a compatible runtime and only when registered through plugin-extension services. [Source: `java-frontend/src/main/java/org/sonar/plugins/java/api/`; `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`.]

## 4. Inputs, recognition, and configuration

### 4.1 Files and Java version

Only indexed files with language key `java` are analyzed. Scanner classification decides whether each is `MAIN` or `TEST`; that classification controls rule scope, classpath, measures, and test-only checks. `sonar.java.file.suffixes` is a project-scoped multivalue override. Its default is `.java,.jav`; after null and blank entries are removed, an empty result falls back to those same two defaults. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/Java.java`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaPlugin.java`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaSensor.java`.]

`sonar.java.source` accepts `X` and `1.X` forms. Invalid values are warned about and treated as unset. Unset source level uses the maximum supported level, Java 26 in this release. `sonar.java.enablePreview` defaults to `false`; preview is honored only for the latest supported Java level and is discarded with a warning for lower levels. A `module-info.java` file is skipped when an explicitly configured source level is Java 8 or lower. [Source: `java-frontend/src/main/java/org/sonar/java/model/JavaVersionImpl.java`; `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/ast/JavaAstScanner.java`.]

### 4.2 Classpath and bytecode

| Setting | Meaning and default |
|---|---|
| `sonar.java.binaries` | Main-output directories containing `.class` files; no default. |
| `sonar.java.libraries` | Main dependency paths or patterns; no default. |
| `sonar.java.test.binaries` | Test-output directories containing `.class` files; no default. |
| `sonar.java.test.libraries` | Test dependency paths or patterns; no default. |
| `sonar.java.jdkHome` | JDK directory used to obtain platform classes; absent or invalid uses runtime-JDK classes. |
| `sonar.java.ignoreUnnamedModuleForSplitPackage` | Defaults to `false`; when true, parsing does not enforce unnamed-module split-package conflicts. |

All paths may be absolute or project-base-relative. Direct library files are accepted when their names end in `.jar`, `.zip`, or `.aar`. Directory and wildcard resolution preserves encounter order and removes duplicates. Main and test classpaths are built separately from their respective binary/library properties plus JDK roots; AutoScan may parse main and test files together with their union. [Source: `java-frontend/src/main/java/org/sonar/java/classpath/ClasspathProperties.java`; `java-frontend/src/main/java/org/sonar/java/classpath/AbstractClasspath.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`.]

When Java files exist, unmatched patterns and missing library properties produce analysis warnings rather than immediate failure. More than one main Java file without `sonar.java.binaries` also produces a precision warning. AutoScan suppresses these presence warnings. An `android.jar` entry marks Android context for checks. [Source: `java-frontend/src/main/java/org/sonar/java/classpath/AbstractClasspath.java`.]

A modular JDK contributes `lib/jrt-fs.jar`; legacy JDK layouts contribute available runtime jars while excluding alternative runtime implementations and duplicate symbolic links. If no configured classpath entry is a recognized JRE archive, ECJ includes the scanner JVM boot classpath. Invalid `sonar.java.jdkHome` falls back with a warning. [Source: `java-frontend/src/main/java/org/sonar/java/classpath/JavaSdkUtil.java`; `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/classpath/AbstractClasspath.java`.]

The class-to-source index records top-level, nested, local, anonymous, and compact-source class binary names. `JavaResourceLocator` maps report class names back to indexed source and exposes matching main `.class` files from binary directories; it does not search arbitrary non-indexed classes as source files. [Source: `java-frontend/src/main/java/org/sonar/java/JavaFilesCache.java`; `java-frontend/src/main/java/org/sonar/java/DefaultJavaResourceLocator.java`.]

### 4.3 Execution and cache controls

| Setting | Default and effect |
|---|---|
| `sonar.internal.analysis.failFast` | `false`; ordinary parser/check exceptions are logged and analysis continues when possible. |
| `sonar.java.internal.failOnStackOverflow` | `true`; when false, a file-level stack overflow is logged and later files continue. |
| `sonar.java.fileByFile` | `false`; forces one-file-at-a-time parsing. SonarLint always uses this mode. |
| `sonar.java.experimental.batchModeSizeInKB` | If absent, an Xmx-derived threshold capped at 500 KB; negative or extremely large values mean one batch. |
| `sonar.java.internal.batchMode` / `sonar.internal.analysis.autoscan` | Internal AutoScan activation. If no explicit batch-size setting exists, main and test files share one batch and classpath. |
| `sonar.internal.analysis.autoscan.filtering` | Defaults to `true` in AutoScan; limits checks to compatible Sonar-way rules plus registered additions. |
| `sonar.java.skipUnchanged` | Optional override. If absent, scanner context decides whether unchanged files may be skipped. |
| `sonar.java.caching.enabled` | Optional override. If absent, scanner context decides whether previous/next analysis caches are enabled. |
| `sonar.java.performance.measure` | Internal diagnostic switch; exactly `true` enables performance output. |
| `sonar.java.performance.measure.path` | Internal diagnostic destination; otherwise the work directory receives `sonar.java.performance.measure.json`. |

[Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`; `java-frontend/src/main/java/org/sonar/java/caching/CacheContextImpl.java`; `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaSensor.java`.]

Unchanged-file optimization first compares an MD5 content hash under cache key prefix `java:contentHash:MD5:`. A matching previous hash is copied forward. Generated JSP-derived files are never skipped. If cache API access or hash computation fails, the analyzer performs full parsing rather than treating the file as unchanged. Checks outside the built-in Java-check package and end-of-analysis visitors remain unskippable; a file is omitted from parsing only when every unskippable scanner can consume its cache input. [Source: `java-frontend/src/main/java/org/sonar/java/caching/ContentHashCache.java`; `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`.]

## 5. Processing stages and lifecycle

1. Plugin registration installs language and classpath settings, rule definitions, built-in profiles, classpath services, Java sensor, measures, external-report sensors, Surefire sensor, warnings, cache services, and extension registrars appropriate to the product. Community Build does not register Jasper. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaPlugin.java`.]
2. The sensor obtains configured Java level, active main/test checks, classpaths, scanner mode, telemetry context, and indexed main/test files. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaSensor.java`.]
3. ECJ parses with latest available JLS grammar, configured compliance, optional preview, binding resolution, and binding recovery. It builds Java syntax trees and semantic environments from source plus classpath. [Source: `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/model/JParser.java`.]
4. Batch mode groups files until the configured byte threshold is crossed. If batch parsing fails unexpectedly, files not yet delivered are retried individually. SonarLint and forced file-by-file mode parse individually. Analysis cancellation stops further parsing. [Source: `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`; `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`.]
5. For each successful file, the frontend creates symbol/reference data, a scanner context, metrics support, and compatible visitors. Java-version and dependency-version gates remove incompatible checks before execution. Main, test, and generated-JSP visitor sets are separate. [Source: `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`.]
6. Checks report issues with a primary file/project location, optional secondary flows, remediation effort, and optional quick fixes. The scanner report and platform own persistence and later issue lifecycle. [Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/reporting/JavaIssue.java`.]
7. End-of-analysis callbacks run, unresolved types and classpath precision warnings are summarized, semantic resources are released, telemetry is aggregated, and optional performance measurement is finalized. [Source: `java-frontend/src/main/java/org/sonar/java/ast/JavaAstScanner.java`; `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`.]

Processing is synchronous within the sensor. Batch parsing may hold a shared semantic environment for a batch; each batch releases it before the next to avoid locked archives. Analyzer state is module/analysis scoped except scanner cache entries, which are transferred through platform previous/next cache contracts. [Source: `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`; `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/caching/`.]

## 6. Outputs

### 6.1 Native issues, locations, and suppression

Only active rules run. Scope `Main` applies to main source, `Tests` to test source, and `All` to both. Primary issue ranges identify the offending syntax described in the catalog; checks may attach ordered secondary locations or flows. A project/file-level issue is allowed when a check has no text span. Empty non-line spans are rejected. `NOSONAR` lines are collected through the platform filter and suppress issues under platform rules. Invalid rule parameters abort analysis as configuration errors rather than silently disabling a rule. [Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`; `java-frontend/src/main/java/org/sonar/java/Measurer.java`.]

The native repository exposes deprecated aliases under repository `squid` unless a rule declares a more specific predecessor. Template rules are `S124`, `S2253`, `S3688`, and `S4011`; they require configured instances. Internal key `S1291` maps to `NoSonar`. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaRulesDefinition.java`.]

### 6.2 Measures and line data

Main files emit `classes`, `functions`, `complexity`, `comment_lines`, `statements`, `ncloc`, and `cognitive_complexity`. Anonymous class bodies do not increase the class count, and methods inside anonymous classes do not increase the function count. Test files emit `ncloc` but not the other Java-owned aggregate measures. Measures are omitted in SonarLint, although `NOSONAR` processing still occurs. [Source: `java-frontend/src/main/java/org/sonar/java/Measurer.java`; `java-frontend/src/main/java/org/sonar/java/metrics/MetricsComputer.java`.]

Main files also emit per-line `ncloc_data` and `executable_lines_data`. Executable lines derive from control-flow instructions, method/initializer bodies, nonconstant initializers, loop endings, lambdas, catch variables, and relevant closing tokens. Every lexical token line contributes to NCLOC line data. [Source: `java-frontend/src/main/java/org/sonar/java/ast/visitors/FileLinesVisitor.java`.]

This artifact registers no Java-specific CPD token sensor and emits no explicit `NewCpdTokens` stream. Duplication detection and derived duplication metrics are scanner/compute-engine contracts, not Java-rule output. [Source: pinned analyzer tree search for CPD extensions; `its/plugin/tests/src/test/java/com/sonar/it/java/suite/DuplicationTest.java`; `manifest/dependency-map.md`.]

### 6.3 Highlighting and symbols

Outside SonarLint, main and test files receive syntax highlighting. Categories are strings/text blocks/character literals, numeric constants, annotations, keywords including context-sensitive restricted keywords, ordinary comments, and structured Javadoc/Markdown comments. [Source: `java-frontend/src/main/java/org/sonar/java/ast/visitors/SyntaxHighlighterVisitor.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`.]

Outside SonarLint, non-generated Java files receive symbols for named classes, class and method type parameters, variables, enum constants, methods, labels, and explicit non-wildcard imports, with semantic references attached. Generated JSP Java deliberately emits no symbol table. [Source: `java-frontend/src/main/java/org/sonar/java/ast/visitors/SonarSymbolTableVisitor.java`; `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`.]

### 6.4 Unit-test execution reports

`sonar.junit.reportPaths` accepts comma-separated absolute or project-relative report directories. If absent, the default is `target/surefire-reports`. A configured missing/non-directory path is an error log; an unconfigured missing default is silent. Each directory first selects files named `TEST-*.xml`; only when none exist does it select `TESTS-*.xml`. [Source: `java-surefire/src/main/java/org/sonar/plugins/surefire/api/SurefireUtils.java`; `java-surefire/src/main/java/org/sonar/plugins/surefire/SurefireJavaParser.java`.]

The importer reads test suites and cases, maps reported class names to indexed Java files, merges inner-class results into the parent source file, and falls back from testcase class name to suite class name. It emits `skipped_tests`, `tests`, `test_errors`, `test_failures`, and `test_execution_time`; `tests` excludes skipped cases. Durations are parsed as seconds and stored in milliseconds; skipped duration is zero. Negative durations are retained in totals with a warning. Unmapped classes are skipped. Malformed XML aborts analysis with a report-specific analysis error. [Source: `java-surefire/src/main/java/org/sonar/plugins/surefire/SurefireJavaParser.java`; `java-surefire/src/main/java/org/sonar/plugins/surefire/data/SurefireStaxHandler.java`.]

### 6.5 External issue reports

| Setting | Engine/repository | Accepted mapping |
|---|---|---|
| `sonar.java.checkstyle.reportPaths` | `checkstyle` | Checkstyle XML `file`/`error`; rule key is the `source` suffix after `com.puppycrawl.tools.checkstyle.checks.`. |
| `sonar.java.pmd.reportPaths` | `pmd` | PMD XML `violation`; priority 1–5 maps to Blocker, Critical, Major, Minor, Info. |
| `sonar.java.spotbugs.reportPaths` | `spotbugs`, `findsecbugs`, or `fbcontrib` | SpotBugs `BugCollection`; bug type selects the bundled external-rule catalog and source path/line identifies the file. |

Configured values resolve to report files through analyzer-commons report-path handling. A missing report is warned and skipped. Missing indexed source files are warned and their issues are skipped. Checkstyle rejects a wrong root, an unrecognized source prefix, or an empty message. PMD uses begin/end coordinates and falls back to the whole begin line when columns are invalid. SpotBugs requires source directories, bug type, source path, and long message. XML readers use the analyzer-commons safe StAX factory. A malformed report is logged and does not prevent another configured report from being attempted. [Source: `external-reports/src/main/java/org/sonar/java/externalreport/CheckstyleXmlReportReader.java`; `PmdXmlReportReader.java`; `SpotBugsXmlReportReader.java`; `ExternalIssueUtils.java`.]

These imported rule IDs belong to their external engines and are not native `java:S…` rules. Their bundled external metadata catalogs do not activate Java checks and are excluded from the native rule count. [Source: `external-reports/src/main/java/org/sonar/java/externalreport/ExternalRulesDefinition.java`; `external-reports/src/main/resources/org/sonar/l10n/java/rules/`.]

## 8. Failure, partial-result, and recovery behavior

- A recognition failure logs the file and parse message. SonarLint records an analysis error; server analysis invokes parse-error-capable visitors on an empty tree. Other files remain eligible. [Source: `java-frontend/src/main/java/org/sonar/java/ast/JavaAstScanner.java`; `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`.]
- An unexpected batch failure retries files not yet delivered in file-by-file mode. A higher-level batch exception stops that source group only unless fail-fast is enabled; cancellation always becomes an analysis-cancelled failure. [Source: `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; `java-frontend/src/main/java/org/sonar/java/JavaFrontend.java`.]
- An individual check exception is logged with check and file identity. Default behavior continues with later checks/files; `sonar.internal.analysis.failFast=true` aborts. Invalid rule parameters always abort. [Source: `java-frontend/src/main/java/org/sonar/java/model/VisitorsBridge.java`.]
- Stack overflow aborts by default. `sonar.java.internal.failOnStackOverflow=false` permits partial continuation after logging the affected file. [Source: `java-frontend/src/main/java/org/sonar/java/ast/JavaAstScanner.java`; `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`.]
- Missing or incomplete bytecode yields unresolved-type and precision warnings; binding recovery permits partial semantic analysis. It does not fabricate resolved symbols. At most 50 unresolved/preview problems are detailed at debug level per reporting cycle. [Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`.]
- Report-import failures are isolated as described in Sections 6.4 and 6.5. Native Java issues and measures already emitted are not converted into coverage results. [Source: report importers cited above; `DroppedPropertiesSensor.java`.]

## 9. Security and trust boundaries

Source text, class files, dependency archives, JDK paths, rule parameters, and XML reports are analysis inputs and must be treated as untrusted. The parser resolves declarations and bindings; it does not require executing project methods or static initializers. [Source: `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`; classpath package.]

Classpath patterns can traverse configured project paths and dependency directories, so scanner filesystem permissions bound readable content. External XML uses safe StAX construction; unresolved report paths and unknown source files are not synthesized. Issue messages from external tools are preserved as external issue messages and remain distinct from native Java rule output. [Source: `java-frontend/src/main/java/org/sonar/java/classpath/AbstractClasspath.java`; external-report readers.]

The Community Java sensor never invokes Jasper and therefore does not load or transpile JSP content. JaCoCo data is neither opened nor interpreted here. These boundaries prevent commercial JSP security behavior or coverage behavior from being inferred into Java analysis. [Source: `sonar-java-plugin/src/main/java/org/sonar/plugins/java/JavaPlugin.java`; `DroppedPropertiesSensor.java`; `manifest/dependency-map.md`.]

## 10. Compatibility and limits

- Maximum source level is Java 26; only Java 26 preview syntax is eligible for preview enablement. [Source: `java-frontend/src/main/java/org/sonar/java/model/JavaVersionImpl.java`.]
- ECJ accepts at most 42,000 compiler warnings per compilation unit. [Source: `java-frontend/src/main/java/org/sonar/java/model/JParserConfig.java`.]
- Default computed batch threshold is capped at 500 KB. It is a grouping threshold, so the file that crosses it remains in that batch. [Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`; `java-frontend/src/main/java/org/sonar/java/BatchGenerator.java`.]
- Cache skipping depends jointly on server support, scanner context permission, hash state, and every unskippable visitor. Configuration cannot force unsupported platform cache APIs into existence. [Source: `java-frontend/src/main/java/org/sonar/java/caching/CacheContextImpl.java`; `VisitorsBridge.java`.]
- Quick-fix publication depends on runtime API compatibility; SonarLint requires plugin API at least 6.3, and SonarQube quick-fix availability requires API at least 9.2. [Source: `java-frontend/src/main/java/org/sonar/java/SonarComponents.java`.]
- Native rule behavior is tied to active rule metadata, Java level, dependency versions, semantic completeness, and source/test scope. No commercial rule registrar may be assumed present. [Source: `VisitorsBridge.java`; `BuiltInJavaQualityProfile.java`; manifest exclusions.]

## 11. Acceptance scenarios

1. **Default recognition.** Given indexed main files ending in `.java` and `.jav`, with the suffix setting absent, empty, or containing only blank entries, analysis includes both and excludes non-Java-language files. Expected output is Java syntax/semantic analysis and active main-scope results for both default suffixes.
2. **Java 26 preview.** Given `sonar.java.source=26` and `sonar.java.enablePreview=true`, a valid Java 26 preview construct parses under preview rules. With source 25 and the same flag, preview is discarded and a warning is emitted.
3. **Misconfigured module source level.** Given `sonar.java.source=8` and an indexed `module-info.java`, that file is skipped with one source-level warning while other Java files continue.
4. **Complete classpath.** Given valid main binaries, dependency archives, and JDK home, external symbols resolve and semantic-dependent active rules execute. Invalid JDK home falls back to runtime JDK and emits a warning.
5. **Incomplete classpath.** Given multiple main Java files and no main binaries/libraries, analysis continues with binding recovery, emits classpath/unresolved-type warnings, and may produce fewer semantic findings rather than invented symbols.
6. **Batch recovery.** Given an unexpected ECJ batch failure after some files were delivered, undelivered files are retried individually. Expected output retains delivered results and attempts remaining files once through fallback.
7. **Fail-fast precedence.** Given one active check throws unexpectedly, default configuration logs failure and continues. With `sonar.internal.analysis.failFast=true`, analysis aborts with a check failure.
8. **Cache hit.** Given platform cache support, unchanged-file permission, identical cached MD5 content, and cache-capable unskippable visitors, file parsing is skipped and previous cache data is copied forward. A hash-read failure causes full analysis.
9. **Main/test separation.** Given one main and one test file, main receives all main-compatible measures and rules; test receives `ncloc`, test/All rules, and no main-only rule.
10. **Surefire default.** Given no `sonar.junit.reportPaths` and valid `target/surefire-reports/TEST-*.xml`, reports map to indexed test classes and emit `tests`, skipped/error/failure counts, and milliseconds. Skipped cases are not counted in `tests`.
11. **Malformed Surefire report.** Given a selected malformed XML file, analysis fails with a Surefire report parse error instead of silently accepting partial data.
12. **Checkstyle import.** Given a configured Checkstyle report with a recognized indexed path, expected source prefix, rule ID, line, and message, one external `checkstyle` issue is emitted at that line. An unknown path emits a warning and no issue.
13. **PMD coordinate fallback.** Given valid begin line but invalid PMD columns, an external `pmd` issue is placed on the whole begin line with severity derived from priority.
14. **SpotBugs engine selection.** Given a bug type present in FindSecBugs metadata, valid source directories, source path, start line, and long message, the issue engine is `findsecbugs`; otherwise the default supported catalog is `spotbugs` unless fb-contrib matches.
15. **JaCoCo boundary.** Given only `sonar.jacoco.reportPath`, Java analysis emits a removed-property warning and imports no coverage. Coverage appears only when the separately owned JaCoCo integration is active and configured.
16. **Rule catalog boundary.** Given Community Build with Java and symbolic-execution plugins, project configuration sees 714 base Java rules plus exactly 23 separately registered symbolic-execution rules under repository `java`; this document does not duplicate those 23 entries.
